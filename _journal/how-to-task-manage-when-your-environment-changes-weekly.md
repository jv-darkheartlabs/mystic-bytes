A new city is a context switch with luggage. The task system has to survive the Wi-Fi, the noise, and the fact that I will forget where I put the charger. Sticky notes die in transit. A board that only lives in a tab I cannot open on cellular is not a system. It is a hope.

I capture before I unpack. Inbox, one list, whatever I already use when I am still. The tool does not get to change because the view changed. If the work was in one place in New Orleans, it stays in that place in Auckland. Migration is how tasks vanish between airports.

Environment change weekly is a specific failure mode. You lose the cues that used to start the work: the same desk, the same kettle, the same hour of quiet. I write the next physical action in the list, not a vibe. "Open the PR" beats "get back into it." When the café is loud, I already know the first step. I do not spend forty minutes remembering what the step was.

I keep a small offline copy of the critical list. Paper in the pouch, or a file that opens without a login dance. The week the apartment internet was a rumor, I still knew what Tuesday was for. Sync when the pipe returns. Do not wait for the perfect network to remember you have a deadline.

This is not the flexible-schedule note. That one is calendar math: overlap hours, when you work, when you stop. This is the capture layer that makes any schedule possible after the room has changed. You can have a beautiful weekly rhythm and still drop a task because the brain spent its working memory on keys, SIM, and which adapter fits the wall.

I batch the admin that travel generates (bookings, banking, the pouch) so it does not contaminate the shipping list. Two lists if I must: work, and move. Mixing them is how "buy toothpaste" sits next to "ship the patch" until both feel fake.

The city can be new every week. The list should not be. Same inbox, next action written, a copy that works when the SSID does not. Then the environment is weather. It is not the project tracker.
