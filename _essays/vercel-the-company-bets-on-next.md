Vercel the company is a bet that Next.js stays the way React reaches a server. Previews, the edge network, the dashboard: those are how you monetize the bet. If Next stopped being the default meta-framework, Vercel would be another git-connected host. The company cannot treat Next as a hobby. The hobby is the moat.

I do not run Vercel for Dark Heart Labs. mystic-bytes is Jekyll. There is a separate micro about Next as React with opinions about the server. This is the firm. Zeit became Vercel. Next stayed the gravitational product. Framework docs, conference talks, and "deploy to Vercel" as the happy path in getting started are one sales motion. Fair. It is also a dependency graph: the best-lit path for a React app is the vendor that named the framework.

A platform micro would talk about previews, serverless functions, and the invoice. Fine. The company thesis is narrower. Keep Next the default, keep the docs warm, keep the "it just deploys" demo one click from `create-next-app`. Competing hosts can run Next. They do not write the tutorial that assumes their logo.

Use Vercel if you are already on Next and you want the path of least resistance. Use Next without Vercel if you can stomach docs that still point home. Do not confuse a platform invoice with a framework law. The company bets on Next because that is the product that makes the platform make sense.

— JV · Dark Heart Labs.
