Version control makes a risky try cheap because the last known-good commit is still there.

I treat dark-heart-themes that way: a contrast experiment, a token rename, a syntax highlight that might be too loud. Branch, try, look at it at night. If it is wrong, revert. The log still records the attempt. Nobody needs a heroic save of a half-broken theme on `main`. I have done the same for mystic-bytes layout spikes that looked clever until they broke the archive list. Git's gift is a reversible narrative. You can attempt the refactor, the spike, the risky API — and return to known good without pretending the try never happened.

Commit often. Small commits are small save points. Write messages for the person who will read them at 2am, including you. Revert without shame when evidence says the ship was wrong. They confuse forgiveness with chaos. Forgiveness here is safety that enables speed: you move because undoing is cheap, not because you are reckless.

A branch that dies is not a failure. It is a hypothesis you did not have to live with. Experimentation requires cheap rollback. Git provides it. Use it, then delete the branch when the evidence is in.

— JV · Dark Heart Labs.
